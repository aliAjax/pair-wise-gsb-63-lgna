# 游乐设施日常检验与缺陷闭环平台

基于Vue3、Naive UI、Pinia、Vue Router、TanStack Query、Axios、WebSocket和Vite的独立前端工程。数据默认保存在localStorage，无需后端即可演示。

## 功能

- 检验任务列表、关键词和状态/区域筛选、统计概览。
- 新建检验任务，逐项录入磨损、异响、制动、锁止和安全装置结果。
- 缺陷处置泳道、风险排序、复测录入（通过/不通过）和闭环审计。
- 状态流转校验、停用隔离、复测与闭环审计。
- JSON记录导出、版本号和完整操作时间线。

## 断网补录 · 回网合并 · 放行闭环

在「断网补传」中心（`/sync`）可完整演示：

- **补传批次带采集时刻和基线**：断网开始时对设备、检验记录、缺陷抓取基线快照，与采集时刻一起随批次保存；回网前不改动任何实体。
- **三方合并、冲突并列保留**：回网时先同步值班室并发改动（重开设备、关闭缺陷、调整责任人），再以批次基线为共同祖先合并；仅一端改动快进采用，同一字段两端都改则并列保留（文本直接并列写入，枚举字段交值班长二选一）。
- **值班长确认前设备锁定**：即使值班室已重开，合并后设备一律重新锁定停用，记录/缺陷暂不可改。
- **复测通过才可关闭缺陷并放行**：值班室在复测回传前关闭的缺陷，合并时判定“关闭被拒”退回待复测；确认时设备上仍有缺陷复测不通过则整批拦截、设备继续停用、不生成放行。
- **按批写入放行**：每台放行设备一条放行记录，某批写入失败只重试这批；已确认/终态批次重放直接拒绝。
- **旧数据首次打开迁移**：v1 数据自动迁移到 v2，补齐基线、派生设备与缺陷、保留原结论（已闭环记录的异常项视为复测通过并补放行）。
- **审计与待办只按当前有效版本**：审计默认只显示 rev 等于实体当前版本的动作，可切换查看历史版本；统计概览只计当前有效缺陷与挂起批次。

两个内置演示场景：批次A（高空飞翔，复测全通过，走冲突裁决→放行，可注入写入失败）与批次B（家庭过山车，一项复测不通过，值班室关闭被拒、设备继续停用）。

## 启动

```bash
npm install
npm run dev
```

访问`http://localhost:18463`。

## 构建与验证

```bash
npm run build   # 类型检查 + 产物构建
npm run verify  # 端到端规则验证（60 项断言：合并/冲突/门禁/放行/重放/迁移/审计）
```
